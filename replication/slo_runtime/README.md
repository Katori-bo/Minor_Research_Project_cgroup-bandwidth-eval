# Independent SLO decision runtime package

This successor also establishes portable import paths in each independent
watchdog/audit/monitor subprocess, verified with fresh Python interpreters.
Both audit writer and reviewer use the dedicated host directory. Any declared
`consumed_allocations` remain closed under their
original package and return seal. They cannot be retried from this successor.
Keep referenced predecessor package directories beside the successor, retaining
their names and full `runs` evidence. Final assembly resolves those original
closed allocations and preserves their costs/unavailable target slots.

This package implements the frozen four-campaign decision study on its declared
host. It contains the sealed scientific v1 snapshot, registered collector
adapters, portable Go/NGINX backends, retained binaries and source closure, and a
dedicated external campaign supervisor. Building and offline checks start no
containers or traffic. Hardware/runtime qualification remains unperformed.

Use Python 3 with the standard library on the declared native Linux x86-64 host.
Runtime prerequisites are rootful local Docker with cgroup v2/systemd, taskset,
systemd-inhibit, sudo, pgrep and working bpftool; the package checks their relevant
properties. It changes no power, tracefs, quota or observer configuration outside
its owned containers. Affinity does not reserve cores exclusively.

The original Intel V31 package is separate and unchanged. Never launch its
historical runner for these campaigns. No historical functional/calibration or
validation outcomes supply the fresh reference. Retained compiled-client build
receipts are software provenance only.

## Offline verification

From this package directory:

```bash
python3 -B runtime/setup.py verify-package
python3 -B -m unittest discover -s runtime -p test_runtime.py -v
```

The tests use synthetic evidence and one harmless Python sleeping subprocess to
verify ownership cleanup. They do not run Docker, HTTP, services, observer
collection, calibration or validation. A passing test suite is not runtime
qualification or proof that the barrier has negligible overhead.

## External setup and future collection

Collection remains held in the research session. The following are instructions
for a subsequently authorized external run, not commands executed by Codex.
Confirm the frozen host allocations and availability first. Quit Codex/ChatGPT
before runtime qualification; stable readable AC power and balanced policy are
required. Setup checks hardware and imports the sealed Go image and NGINX runtime
filesystem without starting services:

```bash
python3 -B runtime/setup.py setup
```

Setup is a separate, recorded image-preparation cost. Go retains its exact image
ID. NGINX imports the byte-identical retained runtime filesystem and records a
fresh Docker metadata ID; it does not claim that ID equals the historical image.
Every service startup verifies the retained runtime files and executable hashes.

Run the host's frozen service order: host01 Go then NGINX; host02 NGINX then Go.
Only after allocation confirmation and authorization:

```bash
systemd-inhibit --what=sleep:idle --mode=block \
  python3 -B runtime/supervisor.py run --application Go --allocation-confirmed
```

Use `--application NGINX` for that allocation. The confirmation flag records use
of the known frozen allocation; it is not inferred from silence and does not
change the scientific design. Any requested host/design change requires a
preserved amendment before outcomes. These commands are intentionally not
launched by package building or offline verification.

The supervisor refuses an existing campaign directory and a service attempted
out of order. A failed or interrupted attempt remains consumed. Preparation,
the retained read-only sudo observer inventory, settling, qualification,
calibration, target warmups, forecast sealing, measurements, reporting and
cleanup all count against 12,600 s (Go) or 2,700 s (NGINX). All four allocated
caps sum to 30,600 s. The independent watchdog stops active work at cap minus
120 s and cleans only saved process identities and matching container nonces.
Authentication is through the original external terminal; passwords are not
passed through the worker log. The inventory uses the unchanged retained audit
and ownership-classification logic, with its fresh evidence under `runs`.

Go requires fresh unreleased resource preflight and all six retained functional
cases, then the full 16-slot capacity/timing prerequisite before selecting all
676 offers from the four declared reference cohorts. NGINX uses three external
100-offer qualification cohorts and four 400-offer calibration cohorts. Failed
qualification never yields validation. Calibration deadlines are sealed before
any target warmup; each later forecast/permit is durable before target Popen.

The worker preserves the first applicability exit as a complete adverse row
when raw integrity and barrier replay establish a complete window. Partial,
corrupt and unobserved windows have no complete-window decision. Final reports
keep all 72 planned study slots; the current host/application report marks other
allocations unobserved, not closed or safe. The study-level return collector
combines all four closed allocations before issuing the final study verdict.
The acquisition ledger records stage wall time, planned offers and actual
parseable raw counts, including functional/preparation requests and full warmups.

Never rerun or remove a failed setup/campaign to obtain a favorable replacement.
Return the entire `runs` evidence directory, including raw failures, ledgers,
receipts, supervisor/watchdog cleanup and reports. Source and raw hashes are
local reproducibility records, not independent timestamp attestations.

To close a genuinely unavailable allocation without starting traffic, use
`runtime/supervisor.py close-unavailable --application Go --reason "host unavailable" --allocation-confirmed`
in its frozen host order. This preserves the planned denominator and cannot be
used to resume or replace an attempted campaign.

Combine the two complete returned packages (including their `runs` directories):

```bash
python3 -B runtime/assemble_returns.py \
  --host-package /path/to/host01-package \
  --host-package /path/to/host02-package \
  --output /path/to/new-study-report.json
```

Assembly performs no live host or Docker checks. It verifies both source
packages and all four return inventories, reconstructs the sealed numerical
decisions from raw warmup/target offers, and preserves the worker's retained
raw/resource classification. It does not claim to rerun every hardware guard
from a relocated package. All unavailable allocations and hard-stop failures
remain in the final report. Setup cost is separate from acquired campaign time.
The preparation raw-cost snapshot is a subset of the campaign acquisition
inventory and must not be added to it twice; control-call counts from the two
worker phases are separate. Existing control requests are counted in memory,
without issuing any additional requests or starting a new hardware observer.
