# Draft amendment: supplemental local SLO decision evaluation

Status: draft for selecting the next route. This document does not authorize
collection, reopen an allocation, change a sealed package or supply a launch
command. The choice between this local supplement and continuing only on Intel
is pending.

## Reason and known information

Both original AMD host01 allocations stopped on documented apparatus errors:
the Go audit output route and the NGINX child watchdog import path. Neither
reached calibration or target evaluation. The Go attempt did acquire functional
preparation outcomes; the NGINX service started during qualification and stopped
before its HTTP client spawned. These failures and the observer ownership review
are known when this draft is prepared. This is not a registration before all
apparatus information was seen.

The corrected runtime v6 packages passed 43 offline checks per host. External
runtime qualification remains unestablished. The full repair record is in
`runtime_io_slo_watchdog_repair_20261011.md`.

## Proposed change

Add a separate supplemental local evaluation with two new allocations, rather
than reopening or relabelling the failed v1 allocations. The proposed identifiers
are `slo_local_supplement01_host01_Go` and
`slo_local_supplement01_host01_NGINX`. Each has 18 fixed target windows and exactly
one attempt. Run Go then NGINX on the same declared AMD host and placement.

Keep the v1 scientific rules: services, software identities, quotas, schedules,
fresh calibration, reference selection, quantiles, fixed deadlines, methods,
miss budget, decision barrier, integrity/eligibility rules and stop conditions.
Introduce no predictor, rate tuning, observer, deadline selection or favourable
outcome requirement. A failure in either supplemental allocation consumes its
18 planned windows; there is no automatic further replacement.

The supplement uses fresh setup evidence and new campaign directories under a
new sealed package with its own scientific identity. It must not reuse v4 setup
records, acquired calibration, warmups or targets. Before any service starts,
the package must verify its amendment identity and offline source receipts.
Native host eligibility and external service qualification still apply before
calibration and target measurement. An existing setup or campaign directory
continues to prohibit overwrite or resume.

## Denominators, cost and interpretation

The original v1 report retains all 72 planned windows, including the 36 unavailable
AMD slots. Its two Intel allocations remain pending under their original plan.
The proposed supplement has a separate 36-window report. Do not substitute
supplemental windows into v1 or describe the supplement as recovering v1
availability. A combined attempt ledger would contain 108 planned slots, with
v1 and supplemental cohorts identified separately; do not pool them into a new
primary result after observing outcomes.

The proposed additional caps are 12,600 s for Go and 2,700 s for NGINX, including
preparation, qualification, calibration, warmups, measurement, analysis and
cleanup, with the existing 120 s cleanup reserve per allocation. This adds
15,300 s (4 h 15 min) of allocated campaign budget to the original 30,600 s,
for a combined planned cap of 45,900 s (12 h 45 min). Preserve all original
elapsed time and acquired offers. Record new image setup and offline engineering
cost separately; neither becomes zero nor is counted twice.

A supplemental AMD event would be a fresh same-host recurrence after an
apparatus correction. It cannot establish independent hardware replication.
The pending Intel v1 evaluation remains necessary for that specific evidence.
Negative, unavailable and applicability-exit supplemental results receive the
same reporting treatment as positive results. Novelty remains unresolved.
